第 12 轮审计：红外强度不在绝对标度上

PySCF 的简正模式已经做过质量加权，代码又除了一次 √m。 氧原子被压到 1/4，而这条谱线被归一化到 100，画出来一模一样。

缺陷 · 简正模式被二次除 √m

红外强度是偶极矩对简正坐标的导数：A = 42.256 · |dμ/dQ|²。 Q 的正确性完全取决于把 dμ/dx 投影到简正模式时用的权重。 PySCF 在 pyscf/hessian/thermo.py 里给出的是：

atom_coords = mol.atom_coords() # Bohr mass = mol.atom_mass_list(isotope_avg=True) # amu norm_mode = einsum('z,zri->izr', mass**-.5, mode)

即 norm_mode 已经是 dx/dQ，且因为 mode 的列是 eigh 的酉特征向量，

sum_a m_a * norm_mode[k,a]**2 == sum_a mode[k,a]**2 == 1 恒等于 1

而原代码写的是：

cart = modes[k] / np.sqrt(masses)[:, None] # 第二次除 sqrt(m) norm = sqrt(sum_a m_a * cart**2) # == sqrt(sum_a modes**2) ≈ 0.96 dmudQ[k] = einsum("axc,ax->c", dmudx, cart / norm)

注释里那个“PySCF 返回的模式没有归一化（0.92–0.96）”是真的， 但量的对象错了：Σ modes² 本来就不该等于 1， 该等于 1 的是 Σ m_a·modes²。于是那个“归一化”把 每个原子的贡献按 1/√m_a 重新加权——水里的氧被压到 1/4， 氢不动。这是质量相关的错误，没有任何单一比例因子能修。

为什么此前一直没被发现

因为画出来的曲线在绘图前被归一化到 100%。一个每条带都强 4 倍的谱， 和一个正确的谱，在屏幕上完全一样。形状对，标度错， 而标度恰恰是论文里唯一会被引用的东西。

裁决：一个不需要任何文献值的求和规则

在质量加权坐标下，正交变换保持平方和；3N−6 个振动模式加上 3 个平动、 3 个转动恰好张满空间，所以

sum_i |dμ/dQ_i|² = Σ_{a,k,α} (1/m_a)(∂μ_α/∂x_{a,k})² − (平动项) − (转动项) 平动：中性分子平移不改偶极 → 0 转动：绕主轴 j 转 dθ 使 μ 转过 |e_j × μ|，该方向的质量加权模长是 √I_j → Σ_j |e_j × μ|² / I_j

这个等式不涉及任何实测强度、任何单位约定，所以它无法被“调常数”满足。 三个候选公式的结果：

常数本身是对的，我先怀疑错了对象

我一开始从第一性原理推这个 42.256，得到 18.35，差一个 ln 10， 一度以为常数也错了。查证后确认：常数正确。Gaussian 官方换算表 （被 Kragskow 的推导完整引用）写的是

1 D²·Å⁻²·amu⁻¹ = 42.2561 km·mol⁻¹ = N_A/(12 ε₀ c²) · kg(u) · D²(C²Å²) "the integrated NAPIERIAN (natural logarithmic) absorbances" 单位：∂μ/∂Q 为 [D Å⁻¹ u^(-1/2)]

我的 18.35 是十进（decadic）版本；km/mol 这个单位在量化界 约定俗成指自然对数版本，两者相差 ln 10 = 2.3026。 这个约定现在写进了 IR_KM_PER_MOL 的注释和结果的 ir_intensity_units 字段——否则一张图注无法说明自己的数字是哪种。

顺带清掉两个说谎的东西： _dipole_at(..., dm0) 收了一个密度矩阵参数，读代码的人会以为 这里是冻结密度导数（缺轨道弛豫项）；实际上 dm0 从未被使用，每个位移点都跑了完整 SCF——最坏的一种：承诺了一个便宜的近似， 实际做了昂贵且正确的事。参数已删。 另有一个从未被引用的 DIPOLE_AU_TO_D_PER_A，一并删除。

变异测试：第一次它没抓住

我把旧写法塞回去，闸门通过了。原因是我把求和规则写成了对 modes 的并行重算，而不是对实际上报的强度的检查—— 守卫测的是副本，无论输出被怎么算出来都会通过。

改成让残差直接由上报的 ir_intensities_km_mol 反推：

vib = sum(intensities_km_mol) / IR_KM_PER_MOL

再注入忠实的旧代码（逐模式归一化，我第一次注入时误写成全局归一化， 残差 −70%，比真实的 −9% 夸张，不算数）。这次两条消息都按预期触发：

[FAIL] IR intensities are on an absolute scale (sum rule closes to <0.5%) - ir/water: the intensity sum rule is off by -9.24% -- the projection onto the normal modes does not conserve sum|dmu/dQ|^2 (got 2.178115, expected 2.399868 D^2/amu/A^2), so the km/mol values are not on an absolute scale - ir/h2s: the intensity sum rule is off by -1.292% (got 0.70875, expected 0.71803). How far off a 1/sqrt(m_a) reweighting lands depends on the mass distribution -- water shows -9.2%, H2S only -1.3% -- so one molecule is not enough to detect it
第二条消息我写错过一次：最初写的是“H₂S 会暴露水看不出的问题”， 而实测恰好相反——水 −9.2%，H₂S 只有 −1.3%。已按实测改正。 断言里出现一句没验证过的因果，就是下一轮的地雷。

闸门与结果

  • ir_sum_rule 现在是 analysis.py 里的公开函数，并在每次 振动分析中随结果返回（水 0.035%、氨 0.008%）。它本身是有意义的物理量， 不只是测试脚手架。
  • contract 新增 3 项：水的求和规则 <0.5%（且断言转动项非零——水的转动项是 振动项的 4 倍，漏掉它会让一个完全正确的投影显示 50% 误差）、 H₂S 的求和规则、ir_intensity_units 必须写明 km/mol。
  • 另加一条逐模式回归（水 79.6 / 1.8 / 20.1，±10%）。求和规则抓的是系统性 错配，这条抓的是“总量对但模式间串了”——两者互补，都不足以单独成立。
  • 界面新增一枚 absolute intensities · sum rule closes to 0.035% 芯片， 悬停显示单位约定；叙述里也直接引用这个残差，而不是让读者去信表头。
